Is Upstox Feasible?

Every claim in this document was checked against the official Upstox developer documentation on 29 October 2026. The short answer is yes — and it is a better fit than the alternative for reasons that go beyond price.

Version 3.0 · Verified 29 October 2026 · Verdict Feasible — proceed · Cost ₹0 / month
Verdict in one paragraph

The Upstox Analytics Token gives free, read-only access to everything this project needs: historical daily candles back to January 2000, live WebSocket market data, and on-demand quotes. It is valid for one year, costs nothing, and — critically — needs no static IP for any of these endpoints. It also cannot place orders, which for a forecasting system is a safety feature rather than a limitation.

One genuine open item remains: written confirmation of data storage, model-training and display rights. That is a commercial question, not a technical one, and it does not block building a private research MVP.

2Upstox vs Zerodha for this project

Both are strong Indian brokers. The comparison below is specific to a system that only reads market data and never places an order. For an execution system the answer could differ.

Upstox Analytics Token Recommended
  • ₹0 per month
  • Token valid 1 year — generate once, set a reminder
  • No static IP for market data → no NAT Gateway → ~$35/mo saved
  • Daily candles from Jan 2000; up to 10 years in one request
  • WebSocket: 5,000 instruments, 2 connections
  • Physically cannot trade — removes an entire category of risk
  • Generous limits: 50 requests/second
Zerodha Kite Connect Not recommended here
  • ₹500 per month — data is not in the free tier
  • Token expires every single day
  • Renewal needs interactive login + 2FA — cannot be fully automated
  • Static IP mandatory for orders → NAT Gateway → ~$35/mo
  • IP changeable only once per week — a mistake blocks you for days
  • Trading-capable credentials in a non-trading system
  • Order rate limit 10/sec
The decisive difference is not the ₹500

The Zerodha access token expires daily and must be regenerated through a browser login with two-factor authentication. There is no supported way to automate this — automating it would mean storing a password and a 2FA seed and driving a headless browser, which is fragile and defeats the purpose of 2FA.

In practice that means a person performs a manual step before 08:30 every working day, forever. Miss it and the day's forecast does not run. The Upstox token lasts a year.

For a system intended to run unattended, this is the difference between a product and a chore.

3The APIs we will use

3.1 Authentication

One header on every request. No OAuth redirect, no daily dance.

Authorization: Bearer <UPSTOX_ANALYTICS_TOKEN>
Accept: application/json

The token lives in AWS Secrets Manager and is read at runtime. It never appears in source code, container images or logs.

3.2 Historical candles — the backbone of training

GET https://api.upstox.com/v3/historical-candle/
    NSE_EQ%7CINE002A01018/days/1/2026-10-28/2021-10-28

Returns an array per candle, in this fixed order:

[ timestamp, open, high, low, close, volume, open_interest ]

[ "2026-10-27T00:00:00+05:30", 250.1, 257.0, 249.2, 255.4, 1254000, 0 ]
UnitIntervalsAvailable fromMax per request
days1January 200010 years

What this means for us

Five years of daily candles for 50 stocks needs 50 requests — one per stock, each covering the full period. At 50 requests/second that is theoretically a second of work; in practice it is a single Lambda invocation with polite pacing. The entire training dataset can be assembled in minutes.

3.3 Live WebSocket feed

Two steps: ask for an authorised URL, then connect to it.

# 1 — get a one-time authorised URL
GET https://api.upstox.com/v3/feed/market-data-feed/authorize
Authorization: Bearer <TOKEN>

{"status":"success","data":{"authorized_redirect_uri":"wss://..."}}

# 2 — connect, then send a BINARY frame (not text) to subscribe
{
  "guid": "stockai-stream-001",
  "method": "sub",
  "data": { "mode": "ltpc", "instrumentKeys": ["NSE_EQ|INE002A01018"] }
}
ModeGives youMax instrumentsOur use
ltpcLast price, quantity, close5,000Our choice — all we need
fullAdds market depth2,000Not needed
option_greeksOptions data3,000Out of scope
Three implementation details that will cost a developer a day if missed

1. The subscription message must be sent as a binary frame, not a text frame. Most WebSocket libraries default to text, and the connection simply does nothing.

2. Incoming messages are Protobuf-encoded, not JSON. You need the official .proto file and a generated decoder. This is the single largest piece of integration work in the data layer — budget a day.

3. The authorise call redirects, and your client must follow redirects. In Node this means setting followRedirects explicitly.

3.4 Quotes — for recovery, not polling

GET /v3/market-quote/ltp?instrument_key=NSE_EQ%7CINE002A01018   # light
GET /v3/market-quote/quotes?instrument_key=...                   # full, 500 per call

Used to fill gaps after a WebSocket disconnect and to sanity-check the stream — not as a substitute for it. Polling 50 stocks every second would burn the rate limit for no benefit.

3.5 Instrument master — refreshed daily, never hard-coded

Upstox identifies instruments by keys like NSE_EQ|INE002A01018. The second part is the ISIN, which is stable. The full instrument file is published daily and must be re-downloaded.

Why this matters more than it looks

Instrument identifiers change — on symbol changes, mergers and corporate restructuring. A hard-coded key that silently starts resolving to a different instrument produces data that is perfectly well-formed and completely wrong. Nothing errors. The model simply learns from the wrong company's prices.

The daily refresh compares every tracked symbol's key against yesterday's and raises an alarm on any change. This is a 20-line safeguard that prevents a class of failure that is otherwise nearly invisible.

The one limit worth planning around

One active token per account. Development, testing and the demo environment would all share it. Generating a new token invalidates the old one, so two developers working simultaneously will interrupt each other.

Mitigation is simple: one token in Secrets Manager, shared by all environments, with a documented rule that nobody regenerates it without telling the team. If that becomes painful, a second Upstox account for development is the clean answer.

None of these are Upstox shortcomings — they are simply outside what a broker's market-data API provides. Each has a known source. The manual curation items (corporate actions, index membership) are roughly two days of setup work and are explicitly budgeted, because skipping them invalidates every backtest the system will ever produce.

6The open question — data rights

This is the only genuine blocker, and it is commercial, not technical

Free API access is not the same as the right to store data indefinitely, train commercial models on it, or display it to the public. Exchange data carries redistribution restrictions that sit underneath whatever the broker's API happens to allow, and the developer documentation does not address these questions either way.

Three questions to put in writing

  1. Storage May we retain historical candle data in our own S3 storage indefinitely, for reproducible research?
  2. Model training May we use that retained data to train machine-learning models, including models that may later support a commercial product?
  3. Display May we display prices and derived forecasts to (a) internal users only, (b) a closed set of invited external users, (c) the general public?
Why this does not block starting

For a private, internal research MVP — invite-only dashboard, no external users, no public display — the risk is low and the activity is ordinary. Build the system, prove the models work or do not, and resolve the rights question in parallel.

What it does block is any public launch. The clarification should be requested in Week 1 so the answer arrives long before it is needed, rather than becoming an emergency later.

7Tests before committing

Roughly two days of work. Do these before the full build, not during it.

  1. Generate the token and make one call Confirms the account is active with eligible segments. Upstox can reject API access when an account has no active segments, so this is worth proving on day one. ~1 hour
  2. Pull 5 years of daily candles for 50 stocks Check for missing days against the NSE trading calendar, verify prices look correct across known stock splits, and confirm the data is split-adjusted or identify that it is not. ~4 hours
  3. Run the WebSocket through a full session Connect before the open, decode Protobuf, deliberately kill the connection mid-session, and verify automatic reconnect and resubscribe. This is the riskiest integration — prove it early. ~1 day
  4. Cross-check prices against a second source Compare a sample of closing prices against NSE's published bhavcopy. They should match exactly. A mismatch means an adjustment or identifier problem. ~2 hours
  5. Deliberately exceed the rate limit Confirm the error response looks as expected and that backoff handling works before it happens during a real backfill. ~1 hour
  6. Send the data-rights questions The three questions in Section 6. Start the clock early — a written answer may take weeks. ~1 hour

8If Upstox does not work out

The architecture deliberately keeps the provider behind a thin internal interface, so replacing it is a contained change rather than a rewrite.

The useful fallback insight

The model training and evaluation work does not depend on live data at all. It needs historical candles, which NSE publishes free as end-of-day bhavcopy files.

So if the Upstox integration stalls for any reason, the most valuable part of the project — finding out whether these forecasts have any real edge — can proceed regardless. Live prices are a dashboard feature, not a research dependency. That is worth knowing before committing a timeline.

9Recommendation

Proceed with Upstox

Technically: everything needed is confirmed available, free, and well within the published limits. Daily history to 2000 is deeper than required, and the WebSocket comfortably handles 100× our instrument count.

Operationally: the one-year token and the absence of a static-IP requirement remove the two biggest sources of daily friction in the alternative design.

Financially: ₹0 per month for market data, and it eliminates the NAT Gateway, saving a further ~$35/month.

Risk-wise: a read-only token that cannot place an order is the correct credential for a system that must never trade.
